# Working notes for Pixel Fishing

This is a static browser game with no build step (since v10.0.0 split into files): a short `index.html` (head, stylesheet links,
loading screen, start card), stylesheets in `css/` and ES modules in `js/` (`main.js` entry, `boot/` loader, `dom.js` + `ui/markup-*.js`
for the page markup, `start.js` + about 150 game modules in folders by system since v10.1.0). Three.js r187 is bundled as one ES module in `vendor/three.r187.module.min.js` and exposed as a
plain global `THREE` by the loader. See `README.md` for the full description of the game, its systems and its structure.

## Always do this with every update

1. **Update `README.md` in the same change.** Update any section the change touches (controls, tables, counts,
   features, technical overview) and add a new entry at the **top of the Changelog** with today's date and a short
   summary. Do not leave the README describing old behaviour.
2. If you add, remove or rename static files (stylesheets, modules, assets, icons), update the file list in the README and
   `js/boot/files.js` (the one list the service worker precaches and the loader counts; a stylesheet also needs its `<link>` in
   `index.html`, in cascade order). Bump `PF_VERSION` (`js/boot/version.js`) for every release: it is shown on the start screen and
   names the offline cache (there is no `CACHE_VERSION` any more).
3. Keep numbers in the README accurate (species counts, bounty pool, option counts, prices). Re-read them from the
   data tables in the modules (`js/data/`, `js/world/layout.js`, `js/town/`…) rather than from memory.

## Conventions

- Models keep their footprint and orientation (fronts face +Z, boats point toward -Z) so collisions and interaction
  ranges stay valid.
- The angler is a skeleton (`AnglerFactory.createRig`: hips, spine, chest, neck, head, clavicles, upper arms, forearms,
  hands, thighs, shins, feet, plus the soft-tissue `bustL`/`bustR` bones last, driven by `AnglerAnimator.bustPhysics`) with a skinned body built in `AnglerFactory.dress`. Change the look in `dress`, the movement in
  `AnglerAnimator`; front is -Z. The rod pivot, chair and bobber stay on `world.anglerGroup`.
- Anything solid gets a collider in the `Colliders` registry (`Colliders.box` / `Colliders.circle` with `COL.WALK`, `COL.BOAT`, `COL.DIVE`) right where its model is built. The walk, boat and dive code all read from it; check with the secret menu's Debug → collision boxes.
- Static pier props are merged by `ModelKit.mergeStatic`; anything that moves or is rebuilt must be passed in its `keep` list.
- World time is `dt` from `animate()`: it is 0 while paused, in a menu or during a freeze frame, so per-frame code must cope with `dt = 0` (no division by it). Random per-frame events use `chancePerSec(rate, dt)`, never `Math.random() < p`.
- The pier's width is `PIER_HW` (rails), `PIER_WALK` (walk limit), `PIER_PILE` and `PIER_DX` (port-side shift of the stairs, mooring platform and moored boat, see `MOOR`); use them instead of raw numbers. The boardwalk runs to +-`BW_HALF`; the mooring platform is `PLATFORM` (with `BOAT_TERMINAL` and `DOCK_PUMP` on it). The boardwalk shops are `SHORE_SHOPS` (position, size, sign; fronts face south) and their goods are `SHOP_KINDS` / `shopItems()`.
- Shops are not menus: goods come from `shopItems(kind, tab)` (data, states, what a purchase does) and their pictures from `WorldBuilder.buildShopItem(key, data)` rendered by `shopPictureFor`; `SHOP_KINDS` lists each shop's tabs, and the Fish Market and Recycling are lists (`shopListRender`). Since v6.7.0 every sheet is drawn by the `ShopUI` builder only (`const U = ShopUI.begin(); U.summary(html); U.item(it); U.row(html, [[label, kind, onClick, disabled, style, aria]]); U.note(html); U.head(text, colour); U.primary(label, onClick, disabled, kind)`): never write sheet DOM by hand; the town sheets use `ShopUI.makeRow` too. Keep it accessible (button labels name the thing they act on; the tablist, focus trap and Esc live in the sheet's keydown handler). A new item needs a model and goes through the confirm dialog (`shopAsk` / `shopConfirmYes`). Use `refreshShopBrowse()` after changing state while a shop is open (it keeps scroll and focus).
- The harbour order (Boatyard, Dive, Tackle, Bounty, pier, Recycling, Fish Market, Aquarium Shop, Cabin) is set by `SHORE_SHOPS`, `RECYCLE` and `CABIN` (the cabin's interior x positions are derived from `CABIN.x`); the harbour map lists the landmarks in `MAP_PLACES`, so add new ones there; the gallery and aquarium (`CABIN.aquaX`) stand inside the cabin (`CABIN.galleryX` and so on; the film camera was removed in v6.6.2, its filters are the drawer's 🎬 Filter row). Since v12.2.0 the cabin stands in town: `TOWN.cabin` in the plan, and `CABIN` (layout.js, same numbers; `z` is the back wall, `floor` the floor height, room spots `shelf`, `wardrobe`, `door` set in `recipes.js` `init`) places the rooms in world units, so every cabin position is `CABIN.x + …`, `CABIN.z + …` (never a bare boardwalk z). The shell is `buildCabin` (wb-cabin.js), the furniture `furnishCabin` (cabin-rooms.js), the deck, garden, colliders and the boardwalk's seating deck (`SEA_DECK`) `cabin-outside.js`. Its walls and roof are fade groups (`userData.fadeWalls` `{ grp, side }`, `userData.roof`), each merged on its own and kept out of the pier merge; `updateCabinFade` fades the roof and the walls the camera is behind while you are inside. The wardrobe and bookshelf are `SPOTS`. The stand zoom is opt-in: only `STAND_VIEWS` entries with `focus: true` (bounty board, aquarium) zoom when you stand still; the rest are used only to frame a shop under its sheet. The cabin's walls and roof are kept out of `mergeStatic` because they fade.
- Boat handling numbers live in `BOAT_TIERS[n].handling`; hull motion is `updateHullMotion`.
- Where the angler stands on a boat is `BOAT_STATIONS[tier]` (and `LH_STATIONS` for the lighthouse jetty, `LH_J`); the casting direction always comes from the station (`boatCastYaw()`), never from `boatYaw` alone. The bounty board's papers are `world.bountyPapers`, redrawn by `refreshBountyPapers`; claim through `claimBounty(idx)`.
- Bounties are chosen by `pickBounties` from what `bountyEligible(b, bountyReach(state))` allows (pier or boat zone, rod weight); a new contract type needs a case in `bountyEligible` and `bountyLevel`.
- The aquarium (Cabin, back wall) is `state.aquarium`: what fits is decided only by `aquariumCanHold` against `AQUARIUM_TANKS` (whose `w`/`h` also size the tank model, rebuilt per tier by `aquaRebuildTank`; owned decorations are `decor` placed + `stored`) (no fish over `AQUARIUM_MAX_W`), daily upkeep and breeding run in `aquariumDay()` from the day-night tick, the fish in the world are `aquaSync`/`updateAquarium`, and its sheet is `aquaRender` (shop sheet kind `aqua`). The tank's `live` group is kept out of `mergeStatic`.
- The day lasts `DAY_SECONDS` (420 real seconds since v6.2.0); in-game minutes are `dt / DAY_SECONDS * 1440`. The day change is `dayRollover()` (also used by the cabin bunk's `sleepTillMorning`). Places the action button can use (bunk, and later town spots) are entries in `SPOTS` (`near`, `prox`, `press`), checked after TALK and the kitchen.
- Meal buffs are charges (`kitchen.buff = { type, n }`, `BUFFS[t].n`), spent with `useBuff(t)` on a cast, a fight start or a dive start; never a timer.
- Skill books are the `BOOKS` table (one per shop, `SHOP_BOOK`); perks are read with `bookBonus(perkId)` (max x minutes read / 21,600) wherever they apply; reading time comes only from the in-game clock via `updateReading(dMinutes)`, never real timers; underwater weights are only ever shown through `diveWeightRange` / `fmtWeightRange` (a per-fish stored seed `estU`).
- Harbour Town (v12.0.0, planned): the town is data in `js/world/town-plan.js` (re-exported by `layout.js`): `ISLAND` (walkable area, `zMax`, the slope `rampZ0`..`rampZ1` up `ISLAND.up` to the Upper Terrace; height `townGround(z)`, terrain flattened by `townFlatten`), `TOWN` (every building and place), `TOWN_BUILDINGS` (the ones with walls, built in order by `buildHarbourTown` on the modern kit `buildModernBuilding` in `town-kit.js`), `STREETS`, `TREES`, `EXTRA_BENCHES`, `JOB_LANTERNS`. Add or move a building only there. Every building has a `face` and a door: use `doorOf(b, out, lat)` and `atDoor(b, x, z)` for door actions, routes, mail stops and NPC spots, never "faces the sea" maths. Door actions are `SPOTS` entries (`post-office.js`); townsfolk houses (`owner`) get a KNOCK action automatically. Townsfolk (`NPCS`, moved by `updateNpcs` along `planRoute`) wait beside doors (`lat` 1.45), never on the door mat. The walking graph (`townNavInit`) is built from `STREETS` plus every door; on the boardwalk routes keep to the lane `BW_LANE` in front of the benches. Matte kit surfaces share roughness 0.9 so a building bakes into about six meshes; window glass and door lamps carry `material.userData.glow` and are switched at night in `updateTownProps` (re-collected when `townFadeState.ver` changes, because fading clones materials). Things that may block the camera are fade groups (`userData.townFade` / `userData.fade`, `updateTownFade`). Town activities use `openTownSheet(title, render)`; their state is `state.town` (`sanitizeTown`); the story is `QUESTS` (`questEvent`, `questTick`, `state.story` via `sanitizeStory`). Boat paint is applied in `WorldBuilder.buildBoatMesh`. Since v12.1.0: a building's own design is its `landmark` field (`resto`, `post`, `boatshed`, `greenhouse`, `tavern`), built by `addLandmark(K, km, b, g, cols)` (`town-landmarks.js` / `-2.js`) in the building's local frame after `buildModernBuilding`; solid parts go into `cols`. A moving part of a building goes in `g.userData.keep` so the fade-group merge leaves it alone (the tavern sign, `g.userData.swing`, swung in `updateTownProps`). Never give a mesh in a fade group a material array (fading clones `o.material`). The square's props are `TOWN.stalls` and `TOWN.well` (`town-props.js`), the street furniture `STREET_PROPS` (`town-street-props.js`, merged in one group). The night glow in `updateTownProps` also collects the boardwalk shops' `userData.glow` materials from `world.pierGroup`.
- Movement (v6.1.1): on foot the stick steers like a car (left / right turn `playerYaw`, up walks along it; down turns round via `revTurn` and walks that way, v6.6.1), speeds and turn rate in `MOVE`, velocity `walkVel`; the camera follows `playerYaw` (`camOrbit.yaw`) plus a drag look offset `camOrbit.look`; tap-to-walk is `autoWalk` built by `planRoute`.
- The restaurant (v6.1) is the player's: `restoName()` from `playerName` (fallback *Fisherman's Restaurant*); recipes are `RECIPES` (with `PANTRY`, `RESTO_UP`, `BUFFS`), saved in `state.kitchen` via `sanitizeKitchen`; service runs from the in-game clock in `updateRestaurant(dMinutes)`; its sheet is shop kind `resto` (`restoRender`), the cooking mini-game is `startCooking` / `cookStep`.
- Anything stored in the save must be validated in `sanitizeSave`. Bump the save version only for breaking changes.
- Deployment is GitHub Pages from `main`.

- Performance (v6.3.1): town buildings are merged with `ModelKit.mergeStatic` per fade group right after they are built (keep anything that changes: signs, toggled parts); what is far or hidden is switched off in `perfCull()` each frame. New town groups that toggle visibility must not be plain meshes at the root of `islandScenery`.
- The menu is a side drawer (`#modal-menu`, rows of `.menu-tile`); the action button hides when it has nothing to do (no Map there; Map is in the drawer and on `M`).

- Friendship (v6.4.0): points in `state.story.friend` via `addFriend(id, n)`; perks are checked with `friendPerk(id)` (8 points, `FRIEND_PERKS`) where they apply (`fuelPrice()`, `modCost()`, `paintDiscount()`, `sellValue` for flora, pantry, maps, dice, `friendPerkTick`). Restaurant cravings are `todaysCravings()` (saved per day in `town.crave`), served in `serveCravings`. Released morphs add `releaseBonus(zoneId)` to the rare-fish bonus in `selectCatchForCurrentZone`.

- Rigs (v6.5.0) are `RIGS` / `state.rig` (`rigState()`): bite time `rigBiteMult()`, catch weights `rigWeight(item)`, the jig's tension help `fightJig`, chum `useChum()` (moves the nearest frenzy behind the boat, `f.chum` makes it visible). Map buoys are `state.buoys` (`dropBuoy`, `syncBuoys`, `buoyPlaces` in `MAP_PLACES`). Dive vents and overhangs are made per prop cell in `makeCell` (`buildVent`, `buildOverhang`, `spawnLurkers`, `updateVents`).

- Endgame (v6.6.0): `PROJECTS` / `town.proj` (`projOn(id)`), the day's weather outlook `dayOutlook(day)` weights `rollWeather()`; the smokehouse hooks the catch overflow (`smokeFits`); the Trophy Wall is `town.wall` drawn by `syncTrophyWall` on the cabin; share codes are `encodeShare` / `decodeShare` (`PF1-` + Base64 JSON, always validated).

- Benches (v6.8.0): `BENCH_SEATS` (seats, `fz` = where you stand) and `EXTRA_BENCHES` (in `town-plan.js`, built with a lamp in `buildTownDistricts`, lamps driven by `updateTownProps`); `benchSeatNear(px, pz, r)` finds a seat, the SIT action is `SIT_SPOT`. Townsfolk are solid circles of `NPC_R` in the walk code and wait in `updateNpcs` while you block them. The rain umbrella is `umbrella` / `ensureUmbrella` (left-hand IK target); umbrellas are built by `makeUmbrella(main, stripe)` and held with `placeUmbrella(u, owner, hScale)` (returns the grip for the IK), townsfolk carry one each (`n.umb`, colours `NPC_UMBRELLAS`), and rain is tested with `isRaining()`; reading points the right index finger (`point` in `AnglerAnimator.update`). Fixed blend colours live in `TINT`, never `new THREE.Color` per frame.

- Interface (v7.0.0, Tide Glass): colours, radii and glass come from the `:root` tokens (`--ink-*`, `--sea`, `--coral`, `--gold`, `--ok/--warn/--danger`, `--glass`, `--glass-strong`, `--blur`, `--r-*`); the TIDE GLASS block at the end of the stylesheet restyles the older components, so put new rules there and use tokens, not raw hex. Icons are symbols in the inline SVG sprite (`<svg class="ic"><use href="#i-name"/></svg>`). The radar, bounty, quest and reading pills are `.trk` items in `#hud-tracker`: set their `style.display` as before and call `syncTracker()` (only the first visible shows, `+N` opens the rest). The cast and fight meters live in the bottom dock (`#center-hud`). Display settings are `settings.textSize` (`TEXT_SCALE`, applied as `zoom: var(--text-scale)` to readable containers, never the controls), `settings.hudAlpha` (`--glass-a`) and `settings.solidUi` (`body[data-solid]`, forced in Battery saver); the pause button is in the drawer header. Since v7.1.0: the drawer's profile card (`#mp-*`) is filled in `updateHUD`; `enhanceModals` turns a header's "Close" button into the round `.g-close` (aria-label from the title), a global Tab handler traps focus in the top open `.modal-backdrop`, and focus goes back to the opener only after keyboard use (`kbNav`); toasts get a kind class from `toastKind(text)`. Since v7.2.0 the old rules no longer carry colours the theme overrides: style new UI in the TIDE GLASS blocks with tokens, use tokens (not hex) in inline `style=""`, keep text at WCAG AA (`--text-3` is the dimmest allowed), and put `backdrop-filter` only on fixed panels, never on scrolling lists.

- Engine (v8.0.0): three.js r187 with `legacyLook()` in the loader (ColorManagement off, linear output on every `WebGLRenderer`, the `lights_pars_begin` chunk patched to the legacy light maths). Mark colour textures with `tex.colorSpace = THREE.SRGBColorSpace` (never `encoding`), keep light intensities in the old units, and do not turn colour management on without retuning every colour. To upgrade three again: rebuild the bundle with esbuild from `node_modules/three/build/three.module.js`, update `PF_THREE_REV` / `PF_THREE_BYTES` / `URL3` / CDN URLs / `PRECACHE`, and check that `THREE.PF_LEGACY_LOOK` is true (the chunk strings still match).
- Draw calls (v8.0.0): static prop groups are merged with `ModelKit.mergeStatic(root, keep, { bakeColor: true })` (or `ModelKit.mergeSafe(group, keep)` for a single prop with glowing parts); anything that changes at runtime (toggled materials, moving parts, per-item lights) goes in `keep`, or shares one material if it always changes together (as the bench lamps do). Characters are baked at the end of `AnglerFactory.dress` by `bakeRig` (see Characters). The shadow map is drawn when `renderer.shadowMap.needsUpdate` is set in `updateSunShadow` (`autoUpdate` is off): set it if you add something that must refresh shadows immediately. The floating thumbstick listens only in the `#joy-zone` square.

- Physics (v8.2.0): Rapier 0.21 (`vendor/rapier3d-compat.0.21.0.min.js`, loaded and `init()`ed by the loader before the game; `window.RAPIER`). `Physics` (right after `Colliders`) mirrors every `COL.WALK` collider into a Rapier world as you register it (keep using `Colliders.box` / `Colliders.circle`). Walking calls `Physics.moveCharacter` (character controller, capsule radius 0.15) between the fixed bound clamps; townsfolk are `Physics.npc(n, NPC_R)` cylinders; town path finding uses `Physics.blocked` / `Physics.segClear`. Always keep the built-in path working: it runs when `Physics.on` is false or `PHYS.walk === 'legacy'`. Boat and dive collisions are still the built-in code (next steps: boat rigid body, dive controller).
- Loading screen (v8.2.0): the loader's `paint()` shows a percentage per step (`#ls-page`, `#ls-three`, `#ls-phys`, `#ls-world`) and overall (`#loading-pct`); a new download goes into `fetchParts` and gets a row and a weight there.

- Characters (v9.0.0, Harbour Chibi): proportions come only from `AnglerFactory.dims` (`torso` scales every height between hips and neck, `legs` the boots and skirt; `headScale` 1.38). Inside `dress()` and `torsoGeo` any new height offset from the hips, spine, chest or neck must be multiplied by `TS` (= `d.torso`) and boot or skirt lengths by `BL` / `d.legs`; the torso profile `prof(y)` is keyed in adult heights (`t / d.torso`). Faces are painted by `AnglerFactory.paintFace(look)` onto the `FACE_PATCH` of the head (one canvas per character, `rig.faceTex`); skin, hair and cloth use `MeshToonMaterial` with the shared `AnglerFactory.toonRamp()` (shiny or metal parts stay standard). Hands are mittens: `S.fingers` is `[mitten, tip]`. Since v9.1.0: colours come from `LookColor.<part>(look)` (a picked `<part>Hex` wins over the palette index); `dress()` runs every look through `sanitizeLook` first (townsfolk looks are partial), so a new look field needs a default in `defaultLook`, a check in `sanitizeLook`, a roll in `randomLook` and a row in `CUST_TABS` (kinds `chips`, `swatch` with `hex`, `slider`, `gender`, `name`, `presets`, `share`; each row names the part the preview frames, `frame`, a key of `CUST_FRAMES`). Garment patterns are vertex colours (`PAT` via `colFn` on `torsoGeo` / `limbGeo`). Expressions are pre-painted face textures: `paintFace(look, expr)` and `AnglerFactory.setExpression(rig, expr)`; `AnglerAnimator.update` blinks and shows `st.expr`. Since v11.0.0: `dress()` ends with `AnglerFactory.bakeRig(rig, fingerBones)`, which merges every mesh it made (skinned body and clothes, and every rigid part skinned to its nearest bone) into one `SkinnedMesh` per material look (toon, basic, standard by roughness/metalness; colours go to vertex colours) on a skeleton of `rig.bones` plus the mitten joints (`S.fingers`, `S.thumb` are `THREE.Bone`s made in `dress`). So anything that must stay separate (a texture, transparency, glow, or a part toggled or recoloured at runtime) needs a material `lookKey` rejects or `userData.noMerge` (the painted face has it), and nothing may reach into a character's meshes after dressing: change the look and dress again. First person hides the head by scaling the head bone (`updateFirstPersonCamera`). The customise screen changes the look only through `custChange(fn)` (`js/ui/customise-history.js`: undo/redo, save, redraw); a change applied bit by bit calls `custRemember()` when it starts and `custCommit()` when it ends. Look codes are share codes of type `look` (`lookToShare` / `lookFromShare`, decoded in `decodeShare`).

- Files (v10.0.0): GitHub Pages serves from a case-sensitive project subpath, so every path is relative (`./css/…`, `./js/…`, never a
  leading `/`), file names are lowercase, and imports are explicit relative paths with the `.js` extension (no bare specifiers).
  `index.html` holds no `<style>`, no inline script, no `style=""` and no `on…=` attributes: styles go in the matching `css/` file
  (new UI in `tide-glass-*.css`, tokens only), markup in `js/ui/markup-*.js` (mounted by `mountMarkup()` in `js/dom.js` before the game
  starts; keep the ids), behaviour in modules with `addEventListener`. Runtime `style=` written by the game's JavaScript (per-value
  widths, colours from tokens) is fine. `file://` does not load modules: test through a local server.
- Modules (v10.1.0): every function, constant and class named in these notes is exported by one module; find it with
  `grep -rn "export .*\bname\b" js/`. Keep files near 100 lines (70–130) and never split a function between files; a function longer
  than that gets a file to itself. Import exactly what you use, with relative paths. Module loading must only declare things: any
  top-level work (DOM lookups, building meshes, listeners, tables computed from other modules, `Math.random`) goes in the module's
  `export function init()`, and a new module with an `init()` is added to `ORDER` in `js/start.js` after everything it needs (the order is
  the old script's top-to-bottom order). A variable that another module must reassign lives on `shared` (`js/state.js`) and is written
  `shared.name` everywhere; imported bindings are read-only. The big classes are split by method: the class file declares the class,
  method files export objects of whole methods (`export const wbTownStatics = { … }`) joined with `addMethods(Class, proto, statics)` in
  the class file's `init()`, so add a method to the group file it belongs to (or a new group, registered in the class file).

## Checking a change

Use headless Chromium (Playwright) against a local copy served over HTTP from a subpath (as GitHub Pages does): boot with no errors (also with a corrupted save), walk the
pier, exercise the menus, and make sure all 69 catch models still build. After a town change, run the town audit: every door's action and sheet, knocking, walking to every door in both walking modes, a fast-forward townsfolk day (no one inside a collider) and the job spots. See the Testing section of the README.
