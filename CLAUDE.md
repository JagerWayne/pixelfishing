# Working notes for Pixel Fishing

This is a single-file browser game (`index.html`, Three.js r187 bundled as one ES module in `vendor/three.r187.module.min.js`, exposed as a plain global `THREE` by the loader). See `README.md` for the full
description of the game, its systems and its structure.

## Always do this with every update

1. **Update `README.md` in the same change.** Update any section the change touches (controls, tables, counts,
   features, technical overview) and add a new entry at the **top of the Changelog** with today's date and a short
   summary. Do not leave the README describing old behaviour.
2. If you add, remove or rename static files (assets, icons, scripts), update the file list in the README, `PRECACHE` in `sw.js`
   and `STATIC` in the loader at the top of `index.html`. Bump `PF_VERSION` (top of `index.html`) for every release: it is shown on the
   start screen and names the offline cache (there is no `CACHE_VERSION` any more).
3. Keep numbers in the README accurate (species counts, bounty pool, option counts, prices). Re-read them from the
   data tables in `index.html` rather than from memory.

## Conventions

- Models keep their footprint and orientation (fronts face +Z, boats point toward -Z) so collisions and interaction
  ranges stay valid.
- The angler is a skeleton (`AnglerFactory.createRig`: hips, spine, chest, neck, head, clavicles, upper arms, forearms,
  hands, thighs, shins, feet, plus the soft-tissue `bustL`/`bustR` bones last, driven by `AnglerAnimator.bustPhysics`) with a skinned body built in `AnglerFactory.dress`. Change the look in `dress`, the movement in
  `AnglerAnimator`; front is -Z. The rod pivot, chair and bobber stay on `world.anglerGroup`.
- Anything solid gets a collider in the `Colliders` registry (`Colliders.box` / `Colliders.circle` with `COL.WALK`, `COL.BOAT`, `COL.DIVE`) right where its model is built. The walk, boat and dive code all read from it; check with the secret menu's Debug → collision boxes.
- Static pier props are merged by `ModelKit.mergeStatic`; anything that moves or is rebuilt must be passed in its `keep` list.
- World time is `dt` from `animate()`: it is 0 while paused, in a menu or during a freeze frame, so per-frame code must cope with `dt = 0` (no division by it). Random per-frame events use `chancePerSec(rate, dt)`, never `Math.random() < p`.
- The pier's width is `PIER_HW` (rails), `PIER_WALK` (walk limit), `PIER_PILE` and `PIER_DX` (port-side shift of the stairs, mooring platform and moored boat, see `MOOR`); use them instead of raw numbers. The boardwalk runs to +-`BW_HALF`; the mooring platform is `PLATFORM` (with `BOAT_TERMINAL` and `DOCK_PUMP` on it). The boardwalk shops are `SHORE_SHOPS` (position, size, sign; fronts face south) and their goods are `SHOP_KINDS` / `shopItems()`.
- Shops are not menus: goods come from `shopItems(kind, tab)` (data, states, what a purchase does) and their pictures from `WorldBuilder.buildShopItem(key, data)` rendered by `shopPictureFor`; `SHOP_KINDS` lists each shop's tabs, and the Fish Market and Recycling are lists (`shopListRender`). Since v6.7.0 every sheet is drawn by the `ShopUI` builder only (`const U = ShopUI.begin(); U.summary(html); U.item(it); U.row(html, [[label, kind, onClick, disabled, style, aria]]); U.note(html); U.head(text, colour); U.primary(label, onClick, disabled, kind)`): never write sheet DOM by hand; the town sheets use `ShopUI.makeRow` too. Keep it accessible (button labels name the thing they act on; the tablist, focus trap and Esc live in the sheet's keydown handler). A new item needs a model and goes through the confirm dialog (`shopAsk` / `shopConfirmYes`). Use `refreshShopBrowse()` after changing state while a shop is open (it keeps scroll and focus).
- The harbour order (Boatyard, Dive, Tackle, Bounty, pier, Recycling, Fish Market, Aquarium Shop, Cabin) is set by `SHORE_SHOPS`, `RECYCLE` and `CABIN` (the cabin's interior x positions are derived from `CABIN.x`); the harbour map lists the landmarks in `MAP_PLACES`, so add new ones there; the gallery and aquarium (`CABIN.aquaX`) stand inside the cabin (`CABIN.galleryX` and so on; the film camera was removed in v6.6.2, its filters are the drawer's 🎬 Filter row). The stand zoom is opt-in: only `STAND_VIEWS` entries with `focus: true` (bounty board, aquarium) zoom when you stand still; the rest are used only to frame a shop under its sheet. The cabin's front wall and roof are kept out of `mergeStatic` because they fade.
- Boat handling numbers live in `BOAT_TIERS[n].handling`; hull motion is `updateHullMotion`.
- Where the angler stands on a boat is `BOAT_STATIONS[tier]` (and `LH_STATIONS` for the lighthouse jetty, `LH_J`); the casting direction always comes from the station (`boatCastYaw()`), never from `boatYaw` alone. The bounty board's papers are `world.bountyPapers`, redrawn by `refreshBountyPapers`; claim through `claimBounty(idx)`.
- Bounties are chosen by `pickBounties` from what `bountyEligible(b, bountyReach(state))` allows (pier or boat zone, rod weight); a new contract type needs a case in `bountyEligible` and `bountyLevel`.
- The aquarium (Cabin, back wall) is `state.aquarium`: what fits is decided only by `aquariumCanHold` against `AQUARIUM_TANKS` (whose `w`/`h` also size the tank model, rebuilt per tier by `aquaRebuildTank`; owned decorations are `decor` placed + `stored`) (no fish over `AQUARIUM_MAX_W`), daily upkeep and breeding run in `aquariumDay()` from the day-night tick, the fish in the world are `aquaSync`/`updateAquarium`, and its sheet is `aquaRender` (shop sheet kind `aqua`). The tank's `live` group is kept out of `mergeStatic`.
- The day lasts `DAY_SECONDS` (420 real seconds since v6.2.0); in-game minutes are `dt / DAY_SECONDS * 1440`. The day change is `dayRollover()` (also used by the cabin bunk's `sleepTillMorning`). Places the action button can use (bunk, and later town spots) are entries in `SPOTS` (`near`, `prox`, `press`), checked after TALK and the kitchen.
- Meal buffs are charges (`kitchen.buff = { type, n }`, `BUFFS[t].n`), spent with `useBuff(t)` on a cast, a fight start or a dive start; never a timer.
- Skill books are the `BOOKS` table (one per shop, `SHOP_BOOK`); perks are read with `bookBonus(perkId)` (max x minutes read / 21,600) wherever they apply; reading time comes only from the in-game clock via `updateReading(dMinutes)`, never real timers; underwater weights are only ever shown through `diveWeightRange` / `fmtWeightRange` (a per-fish stored seed `estU`).
- Harbour Town (v6.0): the walkable island is `ISLAND` (open along the whole boardwalk front since v6.6.1, crossings picked by `frontCrossX`; z up to `zMax`) with buildings in `TOWN`; things that may block the camera go in `world.townFade` (`userData.townFade` / `userData.fade`, faded by `updateTownFade`). The townsfolk are `NPCS` (looks, home, day spots, chat) moved by `updateNpcs` along `planRoute(to, from)`; the story is `QUESTS` (step types handled in `questEvent` for events and `questTick` for states), saved in `state.story` via `sanitizeStory`.
- Harbour Town districts (v6.3.0): ground height is `townGround(z)` (ramp `ISLAND.rampZ0`..`rampZ1`, upper terrace +`ISLAND.up`); terrain under the town is flattened with `townFlatten`. New buildings are in `TOWN` and built by `WorldBuilder.buildTownDistricts` (fade + colliders); town walking routes come from `townPath(a, b)` (waypoints + collider line-of-sight), used by `planRoute`. Town activities (jobs, telescope, dice, traps, paint, greenhouse, Post Office) live in the HARBOUR TOWN LIFE section, use the shared sheet `openTownSheet(title, render)` and are `SPOTS` entries; their state is `state.town` (`sanitizeTown`). Boat paint is applied in `WorldBuilder.buildBoatMesh` (bands via `loftHull`, pennant).
- Movement (v6.1.1): on foot the stick steers like a car (left / right turn `playerYaw`, up walks along it; down turns round via `revTurn` and walks that way, v6.6.1), speeds and turn rate in `MOVE`, velocity `walkVel`; the camera follows `playerYaw` (`camOrbit.yaw`) plus a drag look offset `camOrbit.look`; tap-to-walk is `autoWalk` built by `planRoute`.
- The restaurant (v6.1) is the player's: `restoName()` from `playerName` (fallback *Fisherman's Restaurant*); recipes are `RECIPES` (with `PANTRY`, `RESTO_UP`, `BUFFS`), saved in `state.kitchen` via `sanitizeKitchen`; service runs from the in-game clock in `updateRestaurant(dMinutes)`; its sheet is shop kind `resto` (`restoRender`), the cooking mini-game is `startCooking` / `cookStep`.
- Anything stored in the save must be validated in `sanitizeSave`. Bump the save version only for breaking changes.
- Deployment is GitHub Pages from `main`.

- Performance (v6.3.1): town buildings are merged with `ModelKit.mergeStatic` per fade group right after they are built (keep anything that changes: signs, toggled parts); what is far or hidden is switched off in `perfCull()` each frame. New town groups that toggle visibility must not be plain meshes at the root of `islandScenery`.
- The menu is a side drawer (`#modal-menu`, rows of `.menu-tile`); the action button hides when it has nothing to do (no Map there; Map is in the drawer and on `M`).

- Friendship (v6.4.0): points in `state.story.friend` via `addFriend(id, n)`; perks are checked with `friendPerk(id)` (8 points, `FRIEND_PERKS`) where they apply (`fuelPrice()`, `modCost()`, `paintDiscount()`, `sellValue` for flora, pantry, maps, dice, `friendPerkTick`). Restaurant cravings are `todaysCravings()` (saved per day in `town.crave`), served in `serveCravings`. Released morphs add `releaseBonus(zoneId)` to the rare-fish bonus in `selectCatchForCurrentZone`.

- Rigs (v6.5.0) are `RIGS` / `state.rig` (`rigState()`): bite time `rigBiteMult()`, catch weights `rigWeight(item)`, the jig's tension help `fightJig`, chum `useChum()` (moves the nearest frenzy behind the boat, `f.chum` makes it visible). Map buoys are `state.buoys` (`dropBuoy`, `syncBuoys`, `buoyPlaces` in `MAP_PLACES`). Dive vents and overhangs are made per prop cell in `makeCell` (`buildVent`, `buildOverhang`, `spawnLurkers`, `updateVents`).

- Endgame (v6.6.0): `PROJECTS` / `town.proj` (`projOn(id)`), the day's weather outlook `dayOutlook(day)` weights `rollWeather()`; the smokehouse hooks the catch overflow (`smokeFits`); the Trophy Wall is `town.wall` drawn by `syncTrophyWall` on the cabin; share codes are `encodeShare` / `decodeShare` (`PF1-` + Base64 JSON, always validated).

- Benches (v6.8.0): `BENCH_SEATS` (seats, `fz` = where you stand) and `EXTRA_BENCHES` (built with a lamp in `buildTownDistricts`, lamps driven by `updateTownProps`); `benchSeatNear(px, pz, r)` finds a seat, the SIT action is `SIT_SPOT`. Townsfolk are solid circles of `NPC_R` in the walk code and wait in `updateNpcs` while you block them. The rain umbrella is `umbrella` / `ensureUmbrella` (left-hand IK target); umbrellas are built by `makeUmbrella(main, stripe)` and held with `placeUmbrella(u, owner, hScale)` (returns the grip for the IK), townsfolk carry one each (`n.umb`, colours `NPC_UMBRELLAS`), and rain is tested with `isRaining()`; reading points the right index finger (`point` in `AnglerAnimator.update`). Fixed blend colours live in `TINT`, never `new THREE.Color` per frame.

- Interface (v7.0.0, Tide Glass): colours, radii and glass come from the `:root` tokens (`--ink-*`, `--sea`, `--coral`, `--gold`, `--ok/--warn/--danger`, `--glass`, `--glass-strong`, `--blur`, `--r-*`); the TIDE GLASS block at the end of the stylesheet restyles the older components, so put new rules there and use tokens, not raw hex. Icons are symbols in the inline SVG sprite (`<svg class="ic"><use href="#i-name"/></svg>`). The radar, bounty, quest and reading pills are `.trk` items in `#hud-tracker`: set their `style.display` as before and call `syncTracker()` (only the first visible shows, `+N` opens the rest). The cast and fight meters live in the bottom dock (`#center-hud`). Display settings are `settings.textSize` (`TEXT_SCALE`, applied as `zoom: var(--text-scale)` to readable containers, never the controls), `settings.hudAlpha` (`--glass-a`) and `settings.solidUi` (`body[data-solid]`, forced in Battery saver); the pause button is in the drawer header. Since v7.1.0: the drawer's profile card (`#mp-*`) is filled in `updateHUD`; `enhanceModals` turns a header's "Close" button into the round `.g-close` (aria-label from the title), a global Tab handler traps focus in the top open `.modal-backdrop`, and focus goes back to the opener only after keyboard use (`kbNav`); toasts get a kind class from `toastKind(text)`. Since v7.2.0 the old rules no longer carry colours the theme overrides: style new UI in the TIDE GLASS blocks with tokens, use tokens (not hex) in inline `style=""`, keep text at WCAG AA (`--text-3` is the dimmest allowed), and put `backdrop-filter` only on fixed panels, never on scrolling lists.

- Engine (v8.0.0): three.js r187 with `legacyLook()` in the loader (ColorManagement off, linear output on every `WebGLRenderer`, the `lights_pars_begin` chunk patched to the legacy light maths). Mark colour textures with `tex.colorSpace = THREE.SRGBColorSpace` (never `encoding`), keep light intensities in the old units, and do not turn colour management on without retuning every colour. To upgrade three again: rebuild the bundle with esbuild from `node_modules/three/build/three.module.js`, update `PF_THREE_REV` / `PF_THREE_BYTES` / `URL3` / CDN URLs / `PRECACHE`, and check that `THREE.PF_LEGACY_LOOK` is true (the chunk strings still match).
- Draw calls (v8.0.0): static prop groups are merged with `ModelKit.mergeStatic(root, keep, { bakeColor: true })` (or `ModelKit.mergeSafe(group, keep)` for a single prop with glowing parts); anything that changes at runtime (toggled materials, moving parts, per-item lights) goes in `keep`, or shares one material if it always changes together (as the bench lamps do). Heads are baked at the end of `AnglerFactory.dress`. Townsfolk fingers are hidden by distance with `rigFingers(rig, on)`. The shadow map is drawn when `renderer.shadowMap.needsUpdate` is set in `updateSunShadow` (`autoUpdate` is off): set it if you add something that must refresh shadows immediately. The floating thumbstick listens only in the `#joy-zone` square.

## Checking a change

Use headless Chromium (Playwright) against a local copy: boot with no errors (also with a corrupted save), walk the
pier, exercise the menus, and make sure all 69 catch models still build. See the Testing section of the README.
